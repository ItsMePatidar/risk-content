# 1.2 Probability of Default (PD)

## Definition

**Probability of default (PD)** is the likelihood that a borrower will default within a specified horizon, conventionally the next 12 months. In retail lending, default is normally defined as reaching 90 days past due (90+ DPD), though card portfolios sometimes use 120+ DPD and some IRB definitions add non-payment triggers such as restructuring or write-off. PD is estimated statistically from historical cohorts, not judged case by case, because retail portfolios contain enough homogeneous accounts for frequency to be a reliable estimate of probability. The output of a scorecard is a score; the PD is what that score is calibrated to.

## Why it matters

PD is the single largest driver of expected loss in unsecured retail, where LGD is high and relatively stable. It determines the cutoff (who is declined), the price (risk-based pricing tiers), the limit (how much exposure is granted), and the provision (IFRS9 ECL and Basel capital). Get the PD level wrong and the entire book is mispriced; get the PD ranking wrong and the lender declines profitable customers while accepting loss-makers at the same price. Supervisors examine PD estimation closely because it is the input most susceptible to optimistic assumptions - a model calibrated on 2021-2023 data, a benign period for retail credit, will systematically understate PD in a downturn.

## Formula

Retail PD models are almost always logistic regressions, because the target is binary and the coefficients translate cleanly into a points-based scorecard.

```
logit(PD) = ln(PD / (1 - PD)) = B0 + B1x1 + B2x2 + ... + Bkxk

PD = 1 / (1 + e^-z)   where z = B0 + SUM(Bi xi)
```

where:
- `PD` = probability of default over the modelled horizon, in %
- `B0` = intercept, which sets the base default rate of the development sample
- `Bi` = estimated coefficient for characteristic i; a positive coefficient increases default odds
- `xi` = the value of characteristic i, usually a weight-of-evidence transform of a binned variable rather than the raw value
- `z` = the linear predictor, also called the log-odds of default

The log-odds are converted into a score using two calibration constants:

```
Factor = PDO / ln(2)
Offset = Score_ref - Factor x ln(Odds_ref)
Score  = Offset + Factor x ln(Odds)
```

where:
- `PDO` = points to double the odds, a scaling choice (20 and 40 are common), in score points
- `Score_ref` = the reference score chosen to anchor the scale, in score points
- `Odds_ref` = the good:bad odds at that reference score, expressed as a ratio
- `Odds` = good:bad odds for the account, equal to (1 - PD) / PD

Two calibration regimes exist and must not be mixed:

Point-in-time (PIT) PD reflects current economic conditions and moves with the cycle. IFRS9 ECL requires PIT PD, forward-looking and conditioned on macroeconomic scenarios.

Through-the-cycle (TTC) PD is a long-run average across good and bad years, deliberately insensitive to the current cycle. Basel IRB requires TTC PD so that regulatory capital does not collapse in booms and spike in recessions.

The same borrower therefore has two legitimate, different PDs on the same day. This is a real difference in regulatory intent, not an inconsistency to be reconciled away.

## Worked Example

Example: A personal loan application scored by a four-variable application scorecard. The development sample had a 12-month bad rate of 2.60%, giving an intercept of -3.62.

Applicant profile: bureau score 742, FOIR (fixed obligations to income ratio) 47.5%, two unsecured trade lines opened in the last six months, sourced through a DSA channel.

| Characteristic | Coefficient | Value | Contribution to z |
|---|---|---|---|
| Intercept | -3.62 | - | -3.620 |
| Bureau score, per point above 700 | -0.0059 | +42 points | -0.248 |
| FOIR, per percentage point above 40% | +0.0310 | +7.5 pp | +0.233 |
| Recent unsecured trades >= 2 | +0.4400 | Yes | +0.440 |
| Channel = DSA (vs. direct/digital) | +0.2600 | Yes | +0.260 |
| **z (log-odds of default)** | | | **-2.935** |

Convert to probability:

```
PD = 1 / (1 + e^2.935) = 1 / (1 + 18.82) = 5.04%
```

Convert to a score, using PDO = 20, Score_ref = 600 at good:bad odds of 30:1:

```
Factor = 20 / ln(2) = 28.85
Offset = 600 - 28.85 x ln(30) = 600 - 98.13 = 501.87
Odds   = (1 - 0.0504) / 0.0504 = 18.84
Score  = 501.87 + 28.85 x ln(18.84) = 501.87 + 84.71 = 587
```

The applicant scores 587 against a policy cutoff of 600. At a PDO of 20, those 13 points below cutoff correspond to roughly 1.6x the default odds of a cutoff-level applicant. The decision is not automatically a decline: at a 5.04% PD and 72% LGD, expected loss is 3.63% per annum, so the account is still viable if priced at 18.5% rather than 16.5%. That is the risk-based pricing decision covered in 1.7.

Calibration check. Suppose the model was built on 2022-2023 data with a 2.60% central tendency, but the long-run observed default rate for this segment across a full cycle is 3.45%. The scorecard ranks correctly but sits at the wrong level. The intercept is shifted:

```
B0_adjusted = B0 + ln(0.0345 / (1 - 0.0345)) - ln(0.0260 / (1 - 0.0260))
            = -3.62 + (-3.331) - (-3.626)
            = -3.325
```

Re-scoring the same applicant: z = -2.640, PD = 6.65%. A 32% increase in estimated PD from a calibration adjustment alone, with no change to the applicant and no change to the model's ranking power.

## Common Pitfalls / Misconceptions

- Treating the observed bad rate of a score band as the PD. Observed rates are realised outcomes from one economic period; PD is a forward-looking estimate that requires a central tendency adjustment when the development window is not cycle-representative.
- Assuming lifetime PD is 12-month PD multiplied by tenor. Retail default hazard is not constant - personal loan defaults peak between months 6 and 15 and decline sharply thereafter, so a naive multiplication overstates lifetime PD for seasoned accounts and understates it for fresh ones.
- Ignoring reject inference. A scorecard rebuilt only on approved-and-booked accounts is trained on a censored population and will overstate its own discriminatory power on the through-the-door population it will actually score.
- Silent drift in the default definition. Moving from 90+ DPD to 120+ DPD, or changing how restructured accounts are flagged, breaks comparability with historical PDs and with the provisioning stack downstream. Every PD number should carry its default definition alongside it.
- Confusing rank-ordering with calibration. A model can have excellent Gini and still be badly mis-levelled. These are separate properties and require separate validation tests.
